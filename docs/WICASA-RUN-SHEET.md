## Animated AI, automation and agents sequence

All three introductory technology slides use the same teaching example: **prepare April's GST records for review**, with the note **“April file still pending.”** This is a conceptual scenario rather than a description of GST Fetcher's implementation.

1. **Automation versus AI:** advance a predefined download/save/check sequence; stop on a missing file; interpret the note as an AI suggestion; combine checks with a drafted explanation. A suggestion does not establish whether a file is present.
2. **The AI family:** reveal AI, machine learning, deep learning and LLMs outward-to-inward. The same note appears at the LLM level. A fixed checklist can operate without an LLM.
3. **An AI agent:** give the review-pack goal and tool limits; inspect the folder; observe the missing file; select an allowed retry; recheck and pause for human approval. In this illustrative scenario the retry succeeds; that is not a guarantee about real systems.

Space advances each step without changing slides. R restarts the current animation. The agent's visible tool choices illustrate a model-directed action loop; predefined workflows can also contain branches and retries.

### Office-assistant analogy

Teach the roles in order: **checklist follower → language interpreter → assistant with a goal and approved tools**. Compare the actual instructions: “Check the folder; if missing, retry once; otherwise prepare the pack” versus “Prepare the review folder using approved tools; inspect results and ask for help when needed.” The difference is where action selection comes from: rules you encoded beforehand versus a model participating in selecting actions during execution. Agents still operate inside software, workflows and permission boundaries. Branches, retries and complexity alone do not make a workflow an AI agent.

Name practical implementation options: Excel VBA, Python scripts, workflow tools, or a browser application using HTML for the page and JavaScript for behaviour. HTML alone does not implement the workflow logic. Both automations and agents can use these tools. AI-assisted code generation does not turn an ordinary rule-based program into an agent.

## Three-slide LLM sequence

1. **Learning:** brief history, LLM/GPT, then Space-controlled word zoom, token splitting and token IDs. Continue into an animated neural network: predict, compare the wrong guess with the training example, adjust the connections, then try again. End with parameters and training.
2. **Generating:** prompt and context, then the animated attention example. Continue with Space into neural generation: choose a token, append it, feed back the growing text, and complete the sentence. End with inference.
3. **Memory and judgment:** reveal learned skills, papers arriving on the desk, and an optional saved note brought into a new conversation. Finish with missing context, hallucination, sycophancy and verification.

Space advances one visual step and stays on the same slide after the sequence ends. Right arrow advances the slide. R restarts the current sequence. The three LLM slides resize their content when the viewport or fullscreen state changes.

Token splits and IDs are illustrative. Application memory is optional and does not itself retrain a model. More context and clearer prompts do not guarantee correctness.
